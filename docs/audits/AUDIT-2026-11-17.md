## 2. Method

1. Read the code above end to end, then the invariant tests, and list what each module *claims* against what a test actually asserts.
2. For each suspected gap, write a test that states the correct behaviour and run it. A test that fails proves the gap; a test that passes kills the suspicion (those are listed in §6 so nobody re-walks them).
3. Proven-defect tests live in `tests/defects/AUDIT-2026-11-17.defects.ts`, which `vitest.config.ts` does **not** include (`tests/**/*.test.ts`), so CI's required checks are untouched. Run them with `npx vitest run --config vitest.defects.config.ts`. Each one is written to go green when its defect is fixed, at which point it can move into `tests/invariants/`.
4. No existing test was skipped, deleted or weakened.

Environment limits (see §7): local Postgres was 16, not 17; Prisma's schema engine could not be downloaded, so migrations were applied with `psql` in file order; the sandbox has no IPv6 stack. GitHub CI (Postgres 17, both RLS legs) is the gate.
